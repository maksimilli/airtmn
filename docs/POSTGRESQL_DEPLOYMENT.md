# PostgreSQL и бесплатное размещение: Hugging Face Spaces + Neon

Приложение запускается в Docker Space на Hugging Face, а PostgreSQL работает
отдельно в Neon. В PostgreSQL сохраняются карточки, характеристики, аккаунты,
сеансы и сами PDF (`BYTEA`). Пересоздание контейнера Space не удаляет эти данные.
Каталог сейчас пустой: перенос старых данных не требуется.

## 1. Создайте пустую базу Neon

1. Откройте https://neon.tech/ и зарегистрируйтесь.
2. Создайте проект, например `element`, на тарифе **Free**. Можно выбрать PostgreSQL 16.
3. Откройте **Connect / Connection details**. Выберите базу и пользователя.
4. Скопируйте строку подключения PostgreSQL. Для приложения можно использовать
   **Pooled connection**. Сохраните параметры TLS, включая `sslmode=require` и,
   если он есть в выданном адресе, `channel_binding=require`.

Строка содержит пароль. Не вставляйте её в README, Git, публичные комментарии или
чат. Приложение получает её только через секрет `DATABASE_URL`.

Бесплатные тарифы имеют ограничения объёма и вычислений и могут меняться.
Проверьте текущую пометку Free в аккаунте. Не включайте платный тариф.

## 2. Настройте свой Space

Откройте `https://huggingface.co/spaces/Maximkrutoy/datasheet`, затем
**Settings → Variables and secrets**. Добавьте:

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | `DATABASE_URL` | Строка подключения из Neon целиком |
| Secret | `CATALOG_ADMIN_PASSWORD` | Придуманный пароль администратора, 12–200 символов |
| Variable | `CATALOG_PUBLIC_ORIGIN` | `https://maximkrutoy-datasheet.hf.space` без `/` в конце |

Логин администратора по умолчанию — `admin`. Можно изменить его до первого
запуска переменной `CATALOG_ADMIN_USERNAME`. Если учётная запись уже создана,
изменение bootstrap-пароля в Secrets не изменяет её пароль: используйте управление
администраторами в самом приложении.

Таблицы и первый аккаунт администратора создаются автоматически при первом запуске
приложения. Вручную создавать таблицы в SQL Editor Neon не требуется.

Для другого Space укажите его прямой HTTPS-адрес. Не используйте адрес страницы
`huggingface.co/spaces/...` как `CATALOG_PUBLIC_ORIGIN`.

## 3. Загрузите пакет

Скачайте актуальный архив https://github.com/maksimilli/airtmn/archive/refs/heads/main.zip
и распакуйте. В `deploy/huggingface` находятся **Dockerfile** и **README.md**.

В Space откройте **Files → Add file → Upload files** и загрузите оба файла в корень,
заменив прежние версии. Нажмите **Commit changes**. Новый README содержит
`sdk: docker` и `app_port: 7860`; прежний Static Space переключится на Docker.
Для уже работающего Docker Space эти файлы обновляют версию приложения.
Не загружайте весь архив, папку `data` или файл с паролями.

В Hardware оставьте бесплатный **CPU Basic**. Дождитесь **Building → Running**.
Если приложение сообщает о `DATABASE_URL`, проверьте наличие секрета и перезапустите
Space. Оно не перейдёт незаметно на временную SQLite-базу при отсутствии адреса.

## 4. Проверьте запуск

Откройте `https://maximkrutoy-datasheet.hf.space` отдельно от рамки Hugging Face.
В рамке браузер может блокировать cookie входа.

1. Откройте `/api/health`: ответ должен содержать `"database":"postgresql"`.
2. Войдите как `admin`, загрузите PDF и сохраните компонент.
3. Из отдельного приватного окна проверьте поиск, карточку и исходный PDF.
   Посетителю не доступны загрузка и редактирование.
4. Перезапустите Space и повторно откройте сохранённый компонент и PDF.

Первый запрос после простоя может выполняться дольше: Space и бесплатная база
могут засыпать. OCR сканов выполняется на CPU Space, а не на сервере Neon.

## Хранение и резервная копия

PDF увеличивают объём базы. Ограничение загрузки приложения — 20 МБ на файл;
это не означает, что бесплатный тариф базы позволяет хранить неограниченное число
документов. Следите за использованием хранилища в Neon. Нормальный перезапуск Space
сохраняет данные; удаление базы/проекта Neon удаляет хранилище каталога.

Постоянное хранилище и резервная копия — разные вещи. В проекте есть переносимый
архив карточек, аккаунтов и PDF. Автоматическое расписание пока не настроено.
После установки зависимостей проекта задайте `DATABASE_URL` в приватной среде
терминала и выполните:

```bash
python deploy/backup.py create --archive backups/catalog.tar.gz
```

Архив содержит хеши паролей и должен храниться приватно за пределами Space.
Сеансы входа не включаются в PostgreSQL-снимок. Восстановление выполняется только
в пустую базу по адресу `DATABASE_URL`:

```bash
python deploy/backup.py restore --archive backups/catalog.tar.gz
```

Непустая база не перезаписывается. Не используйте восстановление для слияния каталогов.
Для аварийного сброса пароля через защищённый терминал с `DATABASE_URL`:

```bash
python deploy/reset_password.py admin
```

## Локальный Windows-запуск

`START_WINDOWS.bat` по-прежнему запускает SQLite и локальные PDF, если `DATABASE_URL`
не задана. PostgreSQL не нужно устанавливать на компьютер для обычной локальной
демонстрации. Схема старой SQLite дополняется без удаления карточек или документов.

Если позже понадобится перенести старый каталог, закройте локальное приложение,
сохраните копию всей папки `data` и запустите помощник в среде с новыми зависимостями:

```powershell
.\.venv-windows-312\Scripts\python.exe deploy\migrate_postgres.py --source data
```

Помощник запросит PostgreSQL-адрес скрытым вводом. Целевая база должна быть пустой,
включая аккаунты; выполняйте перенос до первого запуска нового портала. Проверяются
целостность SQLite, связи и SHA-256 каждого PDF. Сохраняются ID, характеристики,
источники и хеши паролей, сеансы не переносятся. При ошибке данные PostgreSQL
откатываются одной транзакцией. Исходная SQLite читается без изменений.

## Если приложение пока остаётся на Render

В Environment того же Web Service добавьте приватную переменную `DATABASE_URL`
со строкой Neon. Оставьте `CATALOG_SERVER_MODE=1`, `CATALOG_COOKIE_SECURE=1`, пароль
администратора и `CATALOG_PUBLIC_ORIGIN`, соответствующий прямому Render-адресу.
Разверните новую версию. PostgreSQL-проверка `/api/health` и проверка PDF после
перезапуска такие же. Переключение платформы само по себе не переносит прежнюю SQLite.

## Проверки разработки

Обычные проверки локального режима:

```bash
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
```

Для проверки PostgreSQL задайте приватно `CATALOG_TEST_POSTGRES_URL` отдельной
тестовой PostgreSQL-базы и выполните ту же команду. Каждый тест создаёт свою схему
и удаляет только её. Существующие API/auth-тесты работают на PostgreSQL; дополнительные
тесты проверяют PDF после смены локального каталога, перенос и откат, последовательности
ID, резервное копирование и восстановление. Используйте тестовую базу, не рабочую.

Схема таблиц создаётся через SQLAlchemy; драйвер подключения — psycopg 3. Используется пул
5 соединений с возможностью временно открыть ещё 5, проверкой соединения перед
использованием и обновлением старых соединений. Запросы параметризованы. Повреждённый
или недоступный `DATABASE_URL` вызывает ошибку, а не переключает данные в SQLite.

Проверка подготовленной версии: 73 теста с PostgreSQL; 67 тестов локального режима
и 6 PostgreSQL-тестов, пропущенных без адреса тестовой базы; сборка обоих Docker-образов;
браузерный сценарий администратора и посетителя; реальное резервное копирование
и восстановление в отдельную пустую PostgreSQL-схему. Образ Space проверен на
порту 7860 от UID 1000, с обязательным подключением PostgreSQL, Secure cookie,
импортом исходного `1n4001.pdf` и OCR сканированной таблицы.
Фактическое подключение к аккаунтам Hugging Face/Neon проверяется после настройки
секретов владельцем; эти сервисы в ходе разработки не создавались.
