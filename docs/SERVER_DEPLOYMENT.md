# Размещение портала в интернете

Посетители просматривают каталог, ищут и сравнивают компоненты без регистрации. Только администраторы могут загружать PDF, добавлять, изменять и удалять компоненты. Кнопка «Войти» открывает форму логина и пароля. Первый администратор создаётся при запуске сервера; дополнительные учётные записи и права доступны в разделе «Администраторы» после входа.

## Что выбрать

Для первого запуска достаточно **VPS/VDS, Ubuntu 24.04 LTS, архитектура x86-64, 2 vCPU, 4 ГБ RAM, SSD от 40 ГБ, публичный IPv4**. Обычный хостинг для статических сайтов или PHP не подойдёт: портал выполняет Python и OCR. Пример провайдеров — [Timeweb Cloud](https://timeweb.cloud/) и [Selectel](https://selectel.ru/); можно использовать другой VPS с Docker. Стоимость и наличие тарифа проверяются у провайдера перед заказом. Выбирайте регион ближе к посетителям.

Отдельно нужен домен, например `catalog.example.com`. В его DNS добавьте A-запись на IPv4 сервера. Если добавлена AAAA-запись, IPv6 также должен вести на этот сервер. Откройте TCP 80 и 443; SSH 22 нужен для обслуживания. Дополнительный порт базы или приложения открывать не нужно.

Compose включает PostgreSQL 16 в закрытой сети Docker. Карточки, аккаунты и PDF сохраняются в её отдельном volume. Распознавание сканов ограничивается ресурсами приложения; массовая одновременная загрузка отдельно не проверялась. Для бесплатного варианта без VPS используйте [Hugging Face Spaces + Neon](POSTGRESQL_DEPLOYMENT.md).

## Установка

Команды ниже выполняются **в терминале Linux-сервера**, а не в командной строке Windows. На Windows к VPS можно подключиться встроенным SSH: `ssh ЛОГИН@IP_СЕРВЕРА`. Не отправляйте пароль сервера или администратора в чат.

1. Установите Docker Engine и Compose plugin по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Проверьте `docker version` и `docker compose version`. При необходимости выполняйте команды Docker с `sudo`; пользователь должен иметь доступ к Docker.
2. Установите Git и Python для помощника настройки, загрузите проект:

```bash
sudo apt-get update
sudo apt-get install -y git python3
git clone https://github.com/maksimilli/airtmn.git
cd airtmn
python3 deploy/configure.py
```

Помощник спросит домен, логин и пароль первого администратора (от 12 символов). Пароль вводится без отображения символов и не выводится в журнал. Конфигурация сохраняется в `.env`, пароль — в `deploy/secrets/admin_password`. Пароль PostgreSQL генерируется автоматически и сохраняется в `deploy/secrets/database_password`. Эти файлы исключены из Git и Docker-образа. Закрытая папка `deploy/secrets` имеет права 700; файл внутри читается контейнером через Docker secret. Не публикуйте эту папку.

3. Запустите:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 app proxy
```

При первой сборке нужен интернет; зависимости и модели OCR затем находятся в образе. Caddy автоматически запрашивает и продлевает HTTPS-сертификат для вашего домена. Для этого DNS должен уже вести на VPS, а порты 80/443 быть доступны. Откройте `https://ВАШ_ДОМЕН`.

Проверка: посетитель видит каталог и кнопку «Войти», без кнопок загрузки и редактирования. После входа первого администратора появляются действия добавления, редактирования и раздел «Администраторы». Загрузите один PDF, сохраните карточку и проверьте её из отдельного окна браузера без входа.

## Что запускается

`Dockerfile` собирает React-интерфейс с Node.js и устанавливает Python 3.12 с FastAPI, PyMuPDF и OCR. Приложение работает без root, с одним Uvicorn worker и постоянным каталогом `/data`. `compose.yaml` запускает приложение, PostgreSQL и Caddy; к приложению можно обращаться только из внутренней сети Docker. Наружу выходят только порты Caddy.

Пароли хранятся в PostgreSQL как PBKDF2-SHA256 с индивидуальной солью и 600 000 итерациями. Сессия действует 12 часов: браузер получает HttpOnly/Secure/SameSite=Strict cookie, база хранит хеш токена. Для изменения данных проверяются права и CSRF-токен; запросы браузера с другого origin отклоняются. Неверные попытки входа ограничены десятью за пять минут с одного IP. Отключение пользователя, смена пароля или прав завершает его действующие сессии. Последнего активного администратора нельзя отключить или лишить прав.

Это не корпоративная система входа: здесь нет почты, восстановления пароля по email, MFA, журналов действий и самостоятельной регистрации. Администратор выдаёт учётные записи и управляет ими. Локальный режим Windows сохраняет работу без входа: доступы включаются только при `CATALOG_SERVER_MODE=1`.

Не запускайте Docker-образ с публично открытым портом приложения: он доверяет заголовкам прокси. Используйте Compose, который размещает приложение во внутренней сети. Не меняйте `CATALOG_COOKIE_SECURE=1` на рабочем HTTPS-сервере.

## Резервная копия и обновление

```bash
bash deploy/backup.sh
```

Скрипт ненадолго останавливает запись, создаёт согласованный снимок PostgreSQL с PDF и аккаунтами, упаковывает его в переносимый архив SQLite и PDF в `backups/` и возобновляет приложение, если оно работало. Хеши файлов и целостность базы проверяются. В течение остановки посетители могут увидеть ошибку доступности. Копия содержит также учётные записи и хеши паролей — храните её приватно и регулярно копируйте за пределы VPS. Только копия на этом же диске не защищает от потери сервера. Можно запускать скрипт по расписанию cron; путь и права Docker должны быть доступны тому пользователю, от которого работает cron.

Перед обновлением сделайте копию:

```bash
bash deploy/backup.sh
git pull --ff-only
docker compose up -d --build
docker compose ps
```

PostgreSQL с PDF находится в `postgres_data`, HTTPS-сертификаты — в volumes Caddy; они сохраняются между обновлениями. **Не выполняйте `docker compose down -v` на рабочем сервере:** эта команда удаляет volumes вместе с данными.

Восстановление выполняется в **пустую** PostgreSQL-базу на новом сервере/отдельном тестовом проекте. Настройте `.env` и пароль, соберите образ, но не запускайте приложение. Положите архив в `backups/` и выполните:

```bash
docker compose build app
docker compose up -d database
docker compose run --rm --no-deps --user 0 -v "$(pwd)/backups:/backups:ro" app \
  sh -c 'python deploy/backup.py restore --archive /backups/catalog-BACKUP.tar.gz && chown -R 10001:10001 /data'
docker compose up -d
```

Замените имя архива на своё. Скрипт проверяет содержимое, контрольные суммы, базу и наличие PDF. Существующие данные не перезаписываются. После восстановления действуют учётные записи из копии; пароль bootstrap не заменяет их. Сеансы из копии сбрасываются, поэтому администраторы входят заново.

## Перенос данных с Windows

Закройте локальное приложение. Передайте **всю папку `data`** на VPS, например SCP/WinSCP, и разместите её в `local-data` рядом с проектом. Выполните импорт до первого запуска в пустую PostgreSQL-базу:

```bash
docker compose build app
docker compose up -d database
docker compose run --rm --no-deps --user 0 -v "$(pwd)/local-data:/source:ro" app \
  sh -c 'python deploy/import_local.py /source /data && chown -R 10001:10001 /data'
docker compose up -d
```

Переносятся карточки и оригинальные PDF. Папка `local-data` не должна попадать в Git или Docker-образ. Если целевая PostgreSQL содержит данные или аккаунты, импорт остановится, сохранив их. Не удаляйте оригинальную папку до проверки карточек на сервере.

## Если забыт пароль администратора

В терминале VPS:

```bash
docker compose run --rm --no-deps app python deploy/reset_password.py admin
```

Замените `admin` на нужный логин. Помощник попросит новый пароль и завершит старые сессии этой учётной записи. Изменение исходного файла `deploy/secrets/admin_password` не меняет пароль уже созданной учётной записи.

## Проверки до публикации

Тесты прав, сессий, CSRF, отзыва доступа и резервного копирования входят в `backend/tests`. Дополнительно проверяются реальный Docker-образ, работа OCR, Caddy, вход и действия браузера. Фактическое размещение и сертификат публичного домена можно проверить только после появления VPS и DNS-записи.

В сетях с собственным доверенным CA сборка поддерживает необязательный BuildKit secret `build_ca`. Передавайте сертификат CA через `docker build --secret id=build_ca,src=/путь/ca-bundle.pem ...`; он используется только при скачивании зависимостей и не включается в образ. Проверка TLS и подписей пакетов остаётся включённой.

Ранее проверенный серверный вариант на SQLite: 66 тестов сервера и 6 тестов интерфейса; сборка Docker-образа; запуск Compose с приложением без root и закрытой сетью; HTTPS Caddy с проверкой цепочки тестового сертификата; вход, отзыв прав и импорт исходного 1n4001.pdf в браузере; сохранение данных после перезапуска; восстановление карточки, учётных записей и PDF в отдельном пустом volume. Публичный сервер и сертификат реального домена пока не созданы.


## Обновление старой VPS-конфигурации на PostgreSQL

Перед переключением сохраните старую папку данных и резервную копию. Не запускайте
новое приложение до переноса: оно создаст первого администратора, после чего
импорт в непустую базу будет отклонён. Старую SQLite не удаляйте.

Если `.env` и секрет администратора уже созданы, помощник настройки их не заменяет.
Добавьте только новый секрет PostgreSQL (скрипт откажется заменить существующий):

```bash
python3 - <<'PYCODE'
import os, secrets
from pathlib import Path
path = Path('deploy/secrets/database_password')
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o444)
with os.fdopen(fd, 'w') as stream:
    stream.write(secrets.token_urlsafe(32) + '\n')
os.chmod(path, 0o444)
PYCODE
```

Затем остановите старое приложение, соберите новую версию, запустите только базу
и перенесите SQLite из прежнего volume приложения:

```bash
docker compose stop app
docker compose build app
docker compose up -d database
docker compose run --rm --no-deps app python deploy/migrate_postgres.py --source /data
docker compose up -d
```

Если каталог пустой, перенос не требуется: достаточно нового секрета и обычного
`docker compose up -d --build`. PostgreSQL не публикует порт 5432 на хост.
